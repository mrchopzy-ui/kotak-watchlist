Login with TOTP Overview

+

+ The Kotak Securities Trade API uses Time-based One-Time Passwords (TOTP) for secure + authentication. The flow is a three-step process: register a TOTP device, validate the + TOTP to receive a view token, and validate MPIN to receive a trade token. +

+
+ Required: Access token from the NEO App API Dashboard (plain token in + Authorization headers). +
+
+ +
+

Step 1: Register for TOTP (one time)

+
    +
  1. Open NEO → API Dashboard → TOTP Registration.
    2. +
  2. Verify with mobile number, OTP, and client code.
    3. +
  3. Scan the QR code with Google/Microsoft Authenticator.
    4. +
  4. Enter the generated TOTP to confirm registration.
    5. +
+
+ +
+

Step 2: TOTP Login (tradeApiLogin)

+

+ Authenticate using mobile number, UCC, and a 6-digit TOTP. On success you receive a + view token and view SID that are used in the MPIN validation step. +

+
+
+

Endpoint

+ POST https://mis.kotaksecurities.com/login/1.0/tradeApiLogin +
+
+

Headers

+ + + + + +
NameValue
Authorization<access_token> (plain)
neo-fin-keyneotradeapi
Content-Typeapplication/json
+
+
+ 
curl -X POST "https://mis.kotaksecurities.com/login/1.0/tradeApiLogin" \
+  -H "Authorization: <access_token>" \
+  -H "neo-fin-key: neotradeapi" \
+  -H "Content-Type: application/json" \
+  -d '{
+    "mobileNumber": "<+91XXXXXXXXXX>",
+    "ucc": "<client_code>",
+    "totp": "<6_digit_totp>"
+  }'
+
+ +
+

Step 3: Validate MPIN (tradeApiValidate)

+

+ Provide your 6-digit MPIN along with the view token and view SID. The response includes + a trade token (Auth), session SID, and baseUrl for all post-login APIs. +

+
+
+

Endpoint

+ POST https://mis.kotaksecurities.com/login/1.0/tradeApiValidate +
+
+

Headers

+ + + + + + + +
NameValue
Authorization<access_token> (plain)
neo-fin-keyneotradeapi
sid<view_sid>
Auth<view_token>
Content-Typeapplication/json
+
+
+ 
curl -X POST "https://mis.kotaksecurities.com/login/1.0/tradeApiValidate" \
+  -H "Authorization: <access_token>" \
+  -H "neo-fin-key: neotradeapi" \
+  -H "sid: <view_sid>" \
+  -H "Auth: <view_token>" \
+  -H "Content-Type: application/json" \
+  -d '{ "mpin": "<mpin>" }'
+
+ +
+

Common Response Fields

+ + + + + + + + +
FieldDescription
tokenJWT token. View token for step 2, Trade token for step 3.
sidSession ID (view or trade).
ridRequest ID for tracking.
baseUrlBase URL to use for all post-login APIs.
kTypeView (step 2) or Trade (step 3).
statussuccess or error.

Quick FAQs

+
+

Which headers do I pass?

+

+ Login APIs use Authorization + neo-fin-key. Post-login + APIs use Auth + Sid + neo-fin-key. Quotes and + Scripmaster only use Authorization. +

+
+
+

Do I use Bearer?

+

No. Always send the token as a plain string.

+
+
+

Rate limits

+

10 requests/second across APIs.
